# 建案客資 CRM — 視覺重設計 demo

Adholic 建案客資系統（`crm.adholic.com.tw`）的介面重設計提案。這個 repo 只放**設計 demo**，不含正式系統程式碼——正式站不受此處任何檔案影響。

## 先看這個

**[`ui-restyle-demo-latest.html`](ui-restyle-demo-latest.html)** — 永遠是最新版。單檔 HTML，字體與 logo 全部內嵌，**下載後雙擊就能開**，不需要伺服器或安裝任何東西。

> GitHub 不會渲染 HTML，在網頁上點進檔案只會看到原始碼。要看設計請下載，或用下方的預覽網址。

## 目前方向：白底鋼藍

| 項目 | 決定 |
|---|---|
| 主色 | 白 `#FFFFFF`；卡片用灰藍 `#F2F5F8`（無框線，靠值階分層） |
| 點綴色 | 鋼藍 `#1D4E6E`（Adholic CI 原色） |
| 燈號 | 紅 `#C4453C` 要人處理／琥珀 `#D9822B` 提醒；**全站只有三個色相**，其餘灰階 |
| 例外 | 意願熱度五點（紅→綠漸層）是唯一的多色元件 |
| 字體 | MiSans TC，四字重（Light 300／Regular 400／Medium 500／Demibold 600） |
| 字階 | 頁標＝KPI 同級（3.1× 內文），中間不設中繼級 |

**完整規範在 demo 裡**：開啟後點左側最下方的書本 icon（設計規範頁），有色彩 token、字階、間距刻度、圓角刻度、元件庫、動態規範，以及參考案的「借用」與「刻意不搬」清單。這頁是給工程師照抄的正本。

建案總覽／建案首頁／來客名單／來客名單（全建案）／銷控表／價格表／分析／業務報表／勾勾表範本／Excel 匯入／業務獎金／人員管理／權限管理／操作紀錄／已刪來客／最新消息／現場收客／設計規範

## 給設計協作者

**這是兩人同時開發的單檔專案，防撞比什麼都重要。** 完整規則見 [`CLAUDE.md`](CLAUDE.md)，重點如下：

### 動手前

- **先 `git pull --rebase`**，再開工。落後的分支改 `latest` 幾乎必定衝突。
- **開工前講一聲你要改哪個區塊**（哪一頁、哪些 class）。兩人同時改同一個 `<section>` 或同一個共用 class＝禁止。
- 從 `main` 開 `feat/<範圍>` 或 `fix/<範圍>` 分支，不要直接推 `main`。

### 動手時

- 顏色與間距**只用檔案開頭 `:root` 裡的 token**（第 13–44 行，共 64 個），不要寫死 hex 或魔術數字。
  白色請用 `var(--on-accent)`／`var(--card)`，不要寫 `#fff`。
- 新增全域 class 前先確認沒撞到既有名稱（單檔 HTML 共用一個命名空間，這裡踩過兩次雷）。
- 頁面專屬樣式寫在該頁的 `/* ── 頁名 ── */` 區塊，選擇器用 `#page-xxx .foo` 限定。
- **只改與任務相關的區塊**，不要順手重排 CSS、格式化或清理「看起來沒用到」的樣式——多半是別頁在用。
- 改到共用區塊（`:root`、`.rail`、`.topbar`、`.chip`／`.pillbtn`／`.circlebtn`／`.kpi`／`.lead`／`.sec`、設計規範頁、JS 共用機制）**一定要通知對方**，PR 標題加 `[共用]`。
- 改了 token 記得同步設計規範頁——那頁是給工程師照抄的正本。

### 交付時

- 大改版另存遞增檔名（`-B10-`），別覆蓋歷史版本；新檔確認能開之後再複製成 `latest`，兩個檔一起 commit。
- PR 用 `.github/pull_request_template.md`，**畫面截圖一定要附**。
- 一次 PR 只做一件事。不要累積成 500 行 diff——單檔 HTML 的大 diff 沒有人能審。

### 紅線

- **建案首頁的照片打底區，底圖必須是業主提供的實景照，不可 AI 生成**（真實標的虛構＝廣告不實）。目前是 `--ph-1`～`--ph-4` 佔位漸層。
- 檔內金額、坪數、戶數皆為示意假資料，對外交付須標示為設計示意。
- **不要引入任何外部資源**（CDN、外部字體、外部 JS、外部圖片連結）。「單檔、離線、雙擊可開」是硬需求。
- **`design-refs/` 是第三方版權素材，已列入 `.gitignore`，絕不可推上 GitHub。** 若在 `git status` 看到它，停手回報。
